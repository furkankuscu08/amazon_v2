# Optional mini-challenges and AWS credits

Checked 2026-09-26 and rechecked 2026-10-14 (organizer replies in the Discussions read 2026-10-18) against [Official Rules §§4, 8](rules.md#4-how-to-enter), [Devpost home](https://amazonappdev2026.devpost.com/), [Resources](https://amazonappdev2026.devpost.com/resources), and [FAQs](https://amazonappdev2026.devpost.com/details/faqs). Mini-challenges layer onto a **primary-track project**; they are not replacement primary tracks. A project can win **one primary-track prize and one mini-challenge prize** (Rules §8). Rules §4 also permits the organizers to reassign a project between categories/mini-challenges where applicable.

## AWS Builder

- **Rules §4:** incorporate AWS services (examples: Bedrock, AgentCore, Strands SDK, Kiro Crew, SageMaker) with **documented integrations** in the primary-track project. **Kiro Crew alone qualifies** as a development tool used during the hackathon; no additional runtime AWS service is required for that case.
- **Submission evidence:** identify AWS Builder as a mini-challenge and explain which AWS service(s) or qualifying tool you used **and how** in Product Feedback (Rules §4). **Recommendation:** describe a concrete workflow and include evidence in the repo/demo where practical; do not claim deployment of a service you only considered.
- Useful starting points: [AWS Builder Center](https://builder.aws.com/), [Learn](https://builder.aws.com/learn), [Kiro Crew](https://github.com/kirodotdev/KiroCrew), [Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/what-is-bedrock.html), [Strands SDK](https://strandsagents.com/docs/user-guide/quickstart/python/), [AgentCore](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html). These are resources, **not** an extra required stack. The [FAQ cost tip](https://amazonappdev2026.devpost.com/details/faqs) suggests turning paid resources off between tests and mocking Bedrock in early development; validate any actual integration before claiming it.
- **Claude Code on Bedrock** ([#45321](https://amazonappdev2026.devpost.com/forum_topics/45321-aws-builder-does-claude-code-running-on-amazon-bedrock-count-as-a-dev-tool)): an organizer reply says Claude Code configured to use Amazon Bedrock as its model provider counts as a qualifying development tool, as Kiro does.
- **Bedrock access on new accounts:** entrants report every Bedrock quota at 0 and not adjustable ([#45416](https://amazonappdev2026.devpost.com/forum_topics/45416-bedrock-blocked-on-a-new-aws-account-all-model-quotas-0-not-adjustable-need-escalation)), "Access to Bedrock models is not allowed for this account" ([#45474](https://amazonappdev2026.devpost.com/forum_topics/45474-bedrock-validation-exception-error)), and access suspended after an account review ([#45384](https://amazonappdev2026.devpost.com/forum_topics/45384-bedrock-access-suspended-hackathon-project-live-demo-affected)). The organizers have no escalation path and point to [u/AWSSupport](https://www.reddit.com/u/AWSSupport) on Reddit. **Recommendation:** confirm a working call early and keep a fallback provider until the integration is validated.
- **AWS Free plan (observed on this project's account, 2026-10-18):** third-party models such as Anthropic's and OpenAI's failed in the playground with `AccessDeniedException` "… is not available for this account", while Amazon Nova worked. AWS's [Free plan documentation](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/free-tier-plans.html) excludes AWS Marketplace, through which third-party Bedrock models are subscribed; upgrading to the Paid plan is one-way. Whether promotional credits cover third-party model charges was not confirmed.

## Open Source

- **Rules §4:** during the hackathon window, create a **new, additional** open-source project (with an open-source license) **or** contribute to an existing public repository, alongside the primary-track submission. Accepted forms include a new repo, branch, fork, or pull request. A PR **need not be merged**; share the forked version if unmerged.
- **Organizer replies:** the primary-track project's own repository does not count, even if new and MIT-licensed ([#45547](https://amazonappdev2026.devpost.com/forum_topics/45547-open-source-mini-challenge-does-the-primary-track-repo-itself-count-as-the-new-open-source-project)); a separate project or a contribution to another public repository is needed. A new repository created during the window for another purpose is eligible, and a mini-challenge is only possible on top of a primary-track submission ([#45310](https://amazonappdev2026.devpost.com/forum_topics/45310-question-related-to-mini-challenge)).
- **Submission evidence:** contribution URL, project repository URL, GitHub username, and a description of **what** changed, **how** it works, and **why** it matters (Rules §4). Identify Open Source as a mini-challenge on Devpost. **Recommendation:** keep the contribution independently inspectable and meaningful; [Rules §6](rules.md#6-judges--criteria) contrasts typo/README-only edits with features, tested fixes, and useful integrations.
- **Timing ambiguity:** the Rules say “during the hackathon window” but do not explicitly define that phrase for contributions. The submission period is **31 Aug 2026, 10:15 Pacific – 23 Oct 2026, 12:00 Pacific** (Rules §1). Plan to complete and link work within that period; if a boundary matters, request written clarification before the deadline (§11.6).
