# Submission checklist

Checked 2026-09-26 against [Official Rules §4](rules.md#4-how-to-enter), [§5](rules.md#5-submission-modifications), the [Devpost submission checklist](https://amazonappdev2026.devpost.com/), and [FAQs](https://amazonappdev2026.devpost.com/details/faqs). **Rules are binding;** the submission form itself requires sign-in and was not independently inspected. Submit by **23 Oct 2026, 12:00 Pacific**.

## Required

1. **Register** for the hackathon on Devpost. If entering as a team/organization, designate an eligible representative to submit on its behalf (Rules §§3–4).
2. **Choose primary track(s)** and indicate any [mini-challenge(s)](mini-challenges.md). For our intended track, state clearly whether you are submitting a [working Agent Skill/MCP integration or a simulated Alexa+ experience](alexa.md). A simulation is an explicit Rules alternative, not a watered-down MCP submission.
3. **Describe** what the project does and how it works. If it existed before **31 Aug 2026, 10:15 Pacific**, explain and show the significant updates built during the submission period.
4. **Provide a GitHub repository URL** with all source, assets, and setup/run instructions needed to make the project functional. The [FAQs](https://amazonappdev2026.devpost.com/details/faqs) confirm GitLab or other non-GitHub hosting does not satisfy the Rules. Choose one:
   - **Public:** include an open-source license file; the Rules say it should be detectable and visible at the top of the repo page (About section).
   - **Private:** grant access to **both** `testing@devpost.com` and all six Amazon reviewers: `chris-trag`, `knmeiss`, `giolaq`, `anishamalde`, `mosesroth`, `emersonsklar`. See the [GitHub collaborator walkthrough](https://docs.github.com/en/account-and-profile/setting-up-and-managing-your-personal-account-on-github/managing-access-to-your-personal-repositories/inviting-collaborators-to-a-personal-repository). The [Devpost update](https://amazonappdev2026.devpost.com/updates/46456-got-an-idea) says invitations expire in seven days and recipients must accept: invite around submission time and re-send expired invitations. Public repositories need no reviewer invitation.
5. **Demonstrate the project working.** For Alexa+ simulation, the repo must contain the simulation's source and the video must clearly show the simulated experience. For the real Agent Skill/MCP route, demonstrate the working technology at runtime in code (not merely named in README) and in the demo; see [Alexa+ details](alexa.md). For other tracks see [Rules §4](rules.md#4-how-to-enter).
6. **Publish a demo video** publicly on **YouTube or Vimeo** and submit its link. It **should be under three minutes**; judges need not watch beyond 3:00. Show the working experience for its intended platform. Do not use third-party trademarks, music, or footage without permission. The [FAQs](https://amazonappdev2026.devpost.com/details/faqs) discuss attributed footage, but the Rules' permission requirement prevails.
7. **Answer Product Feedback for each developer tool, API, or SDK used**: what you used and why; what worked (setup, docs, testing, performance, reliability); what needs improvement (errors, missing features, limitations, workarounds); onboarding from zero to hello world; and whether you would build with these devices/services again, yes/no and why. If entering AWS Builder, describe each AWS service used and how in this answer; if entering Open Source, supply its separate [contribution evidence](mini-challenges.md#open-source).

**Language conflict:** the Devpost checklist says the video is “in English”; [Rules §4 Language Requirements](rules.md#language-requirements) allow English **or an English translation** of the video, written description, testing instructions, and other submitted materials. Follow the Rules.

## Optional, but useful

- **Feature requests:** request, why it matters to the project, and priority (Critical / Important / Nice-to-have).
- **Friction log:** each entry records the attempted task, steps, expected vs actual result, severity, workaround, and actionable suggestion. Under [Rules §6](rules.md#6-judges--criteria), Amazon's Stage One reviewers recommend up to a **10%** bonus for Stage Two, whose panel applies it to the final score. The log is optional, not a substitute for required Product Feedback. **Recommendation:** capture issues while building rather than reconstructing them at submission.

## Testing, rights, and final checks

- Keep the code repository and video accessible; if your website is private, include login credentials in testing instructions. The project must be available **free of charge and without restriction** to Sponsor, Devpost, and judges until the judging period ends (**20 Nov 2026, 12:00 Pacific**). Judges may instead score only the description, images, and video. The [FAQs](https://amazonappdev2026.devpost.com/details/faqs) say a locally runnable public Alexa+ repo plus video is enough; a continuously deployed service is not inherently required, but supply runnable instructions and required judging access.
- Your entry must be original, owned by the entrant, and authorized to use any third-party SDKs, APIs, media, and data. Follow open-source licenses. Special non-widely-available hardware can trigger a request for physical access (Rules §4).
- Multiple entries are allowed only if unique and substantially different. Sponsor/Devpost financial or preferential support for developing the project can disqualify it (Rules §4).
- After the deadline, **do not assume you can edit the submitted Devpost entry**: Rules §5 forbids changes except narrowly permitted IP, privacy, or inappropriate-content fixes. Recheck the live [Rules](https://amazonappdev2026.devpost.com/rules) immediately before submitting.
