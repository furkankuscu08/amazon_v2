## Decisions so far

- **One story, three questions.** The opening asks the three questions a new idea raises, and each segment answers one in turn: is someone already on it (Noah in the live run), who handles it now (Tara and Omar on the saved marketing-spend plan), and who is missing (the open area on the saved stablecoin plan, shown as WorkBot saying where it found no one, not as proof that the work is unowned: Legal and Compliance has a manager whose remit covers compliance). The Devpost text's "Three questions it answers" section uses the same three moments. The narration never says that work was done twice or that any work has no owner.
- **The opening states the problem without a measured number** ("In a company of thousands, the person you need is usually on another team, and the name on an old document may no longer own the work."): "a company of thousands" describes the setting, not a result; no company size or time saving was measured, and the synthetic company has 49 people, as the Devpost text says.
- **The live run comes first**, right after the opening, so a working app is shown in the first minute. Noah is "already on part of it": the record is a Jira issue assigned to Noah for a table the idea needs, not the idea itself, and not proof that the table is finished.
- **"How did it find Noah?"** bridges from the live result to the diagram, which is walked through in pipeline order, steps 1 to 6, with the box being described highlighted and the rest dimmed (a judge found the undimmed diagram too dense to read while listening). It names what each step uses: Nova 2 Lite's areas and keyword-and-meaning searches (`models.SearchIntent`), retrieval over every record Maya can see, indexed by keyword (SQLite FTS5, BM25) and as embeddings in Qdrant (`search.index_visible_records`, `Searcher.records`), the shortlist of people tied to the records (`search.candidate_pool`, which also adds people in the area's team whose current duty matches, and the team's manager when the team's remit matches), the parallel area reviews, the audit, the priority call that can never add anyone, and code building the plan, Alexa's summary and every follow-up answer. The narrator says "Quadrant" to the speech engine so that Qdrant is pronounced right; the subtitles spell Qdrant.
- **Who handles it now** is the Tara and Omar contrast on the Finance card: Tara reviews these requests today, Omar wrote the 2024 policy but no longer approves, so Maya asks Tara about today and Omar about the history (both other models advised naming the contrast; it is what makes both names useful). The proof of Omar's ended role is the directory record, so the video opens the **Source** link on the ended-role note, not the policy document, and says over it that the AI never sees ended duties and code adds the dated note (`search` passes only current, visible duties to the model calls, `service._ended_duty` adds the note, and the priority call never receives it).
- **The withdrawn plan** is said once, after the open area: "If a cited record or person changes, the plan is withdrawn." It says cited, not anything: `storage.dependency_snapshot` covers cited sources and their links, the people on the card, routing managers, and the org inventory, but not uncited search results, directory hints, or new records, so an open area is not withdrawn when a relevant record appears. The screen does not show a withdrawn plan; showing one would need a hosted plan to be changed, which the user did not want.
- **The close** gives the reason for Alexa+ and the audience: the question comes up mid-task, Alexa gives a few names you can hear while the screen keeps the evidence, and for anyone planning a change across teams new work starts with the right people. The tagline "Before you start, know who to talk to." is on the end card.
- **Saved plans carry no caption**: earlier cuts labelled them "Saved plan from an earlier version · new runs can differ", which the user removed on 22 October because it looked bad. The narration marks them instead ("Here is a live run", "On the saved marketing-spend plan", "On a saved plan for another idea"), and the live run keeps its own labels, so nothing presents a saved plan as live or the other way round.
- **Two voices**: a narrator (Google Gemini 3.8 Flash TTS, the voice Kore, called through OpenRouter; the user chose it over the Polly standard voices, the only ones the demo's Region offers, which sounded mechanical), and the app's own voice (Amazon Polly, Brian, which the user chose over the other standard voices; it reads the plan summary and follow-up answers), taken from the app's own audio for the same text. The app's voice calls each person on the plan by first name (the full name when two on the plan share it), because the standard voice mispronounced surnames; the page shows full names. The narrator never speaks over the app's voice (at least 1 second apart), and every voice is mixed at the same loudness. Two versions are cut, one with the narration as burned-in subtitles and one without; the one without is uploaded, with the narration as a separate caption file. The labels (synthetic voice sample, live run) are in both. Maya is never heard: **Speak** is fed a synthetic voice sample, captioned as such; the video plays that sample while the page listens (two judges found the silent Speak segment looked broken) and then shows the box filling.
- **Length**: 2:58 in all, with about 330 narrated words; the app's voice takes 17.2 seconds in the live run (the first two sentences of the summary and "Why Noah?" through the quoted Jira issue) and 6.3 on the stablecoin plan. The measured result (39 of 42 live runs passed the answer key) is left to the Devpost text.
- **Wording**: "The AI" is used where it stands against code ("The AI proposes; code verifies"); "Nova 2 Lite" or "Nova 2 Sonic" where one call is meant. The narration does not call WorkBot agentic or multi-agent: code fixes the order of the three model tasks, and each call is forced to one schema. It says "Alexa's summary and every follow-up answer", never "every word Alexa says", because a clarification question is model-written and is read aloud too.
- The live segment runs customer scoring: Noah Baker came first in all 5 measured runs with directory hints, and was first on the recorded live plan too. The home page already holds a saved plan for that idea, so the live run repeats it; its plan may differ from the saved one, and the video does not compare the two.
- "Prep me for Tara" and "Why Omar?" stay out of the video; ideas whose stored cards showed a wrong direct contact (pickup lockers, campaign AI) stay out too.
- Claims stay within what the code does: code checks record visibility and the person's link to it, not whether a record answers the area's question; the card shows no model-written summary of a person; the only model-written text on the page is the area names, what to find out, the shared question, and a clarification question. On the cards, each person's evidence line links to its record, except a routing contact's; "What to find out" has no source.
- No gendered pronouns for any person, Maya included.
